## 一、HIGH

### 1.1 JPEG「无损」压缩丢掉已计算的缩放

- **文件:** `backend/engines/compressor.py`（约 450–463 先 `_resize_image`，624–652 无损分支回读原文件）
- **描述:** 缩放成功后，JPEG lossless + MozJPEG / 字节复制仍 `open(input_path)` 优化或拷贝**原文件字节**。返回字典里的 `width`/`height` 是缩放后的尺寸。
- **失败场景:** 4000×3000 JPEG，无损档 + 50% 缩放 → API 报 2000×1500，磁盘仍是原图像素。PNG 无损+缩放有测试；JPEG 没有。
- **建议:** 已缩放时禁止走原文件字节路径，改为对内存中的 `img` 再编码；或 lossless+resize 明确降级并警告。

### 1.2 拼接按未旋转尺寸排版，粘贴时却做了 EXIF 转正

- **文件:** `backend/engines/stitcher.py`（probe 约 136–139 用 `Image.size`；`_load_scaled` 约 49–61 走 `exif_transpose`）
- **描述:** 宫格 / 分割 / 缩放 / 水印都是先转正再量尺寸。拼接 probe 用文件头尺寸，加载路径转正后再按错误槽位粘贴。
- **失败场景:** 两张 iPhone 4032×3024、Orientation=6，纵向拼接 → 画布按横图算宽，转正后的竖图被塞进错误格子，重叠或裁切。
- **建议:** probe 与 `_load_scaled` 使用同一套「转正后再量」逻辑。

### 1.3 转换（以及 PDF 排版）不做 EXIF 转正

- **文件:** `backend/engines/converter.py`（约 407–430）；`backend/engines/pdf_generator.py`（约 250–253）
- **描述:** 转换只有 `Image.open` + `load()`。`keep_metadata=false` 时像素侧着且无方向标签；`true` 时标签还在，但缩放发生在未旋转缓冲上。PDF 用文件头尺寸、不转正。
- **失败场景:** 典型相机 JPEG（Orientation=6）转 PNG/JPEG 或进 PDF → 预览器里横着，或尺寸与元数据不一致。
- **建议:** 打开后立刻 `ImageOps.exif_transpose`；保留 EXIF 时去掉已应用的 Orientation 标签。

### 1.4 缩略图 SVG 绕过安全检查；转换失败会落到无超时 Inkscape

- **文件:** `backend/api/desktop_api.py` `_render_thumbnail_bytes`（约 327–330）；`backend/engines/converter.py` `_svg_to_pil`（约 219–262）；`backend/engines/_svg_ops.py`
- **描述:** 缩略图对 `.svg` 直接 `resvg_py.svg_to_bytes`，不调用 `assert_svg_render_safe`。转换路径里 resvg 失败会跑本机 Inkscape，无 subprocess 超时。正则漏掉 CSS `url(https://…)` / `url(file://…)`。
- **失败场景:** 拖入带外部引用的 SVG → 预览即可触发渲染/外连；转换失败时 Inkscape 再放大一次。
- **建议:** 缩略图与转换共用 `assert_svg_render_safe`；resvg 失败即失败，或 Inkscape 加超时且不再打开未校验文件。

### 1.5 转换 / 尺寸调整输出像素无上限

- **文件:** `backend/engines/converter.py`（约 435–465）；`backend/engines/resizer.py`（约 56–72）
- **描述:** `Image.MAX_IMAGE_PIXELS = 64_000_000` 只限制解码。转换 `scale_percent` / `long_edge` / 固定宽高只有 `max(1, …)`；缩放引擎允许 1000% 或 30000px 边。拼接 / GIF / SVG 有面积帽，这两处没有。UI 滑条（转换 200%、缩放 500%/8000px）挡不住直接调 API；转换「最长边」还是未封顶数字框。
- **失败场景:** 接近解码上限的图再放大 → 工作进程先把机器打满，然后才 `MemoryError`。
- **建议:** 与 stitcher 对齐（例如边 16000 / 面积 256MP），超限返回明确错误码。

### 1.6 调大进程池会取消正在跑的批处理

- **文件:** `backend/application/image_ops.py` `_get_pool`（约 87–104）
- **描述:** 目标 worker 数变大时 `shutdown(wait=False, cancel_futures=True)` 再新建池。测试全程 `IMAGEFLOW_DISABLE_PROCESS_POOL=1`，这条路径没有覆盖。
- **失败场景:** 批处理进行中把并发从 4 调到 8 → 未完成 future 被取消，结果变失败/取消，磁盘可能半成品。
- **建议:** 扩容等到当前批结束再换池，或新建池承接新任务、旧池 `wait=True` 收尾。

### 1.7 增量拖入会覆盖已选文件列表

- **文件:** `frontend/components/FileDropZone.tsx`（约 627–636）
- **描述:** 已知路径快路径先 `mergeAndPublishResult`，后台 `ExpandDroppedPaths` 返回后**整表替换**成这一次的结果。`OnFileDrop` 走 merge，这条不走。
- **失败场景:** 先拖文件夹 A，再拖 B；A 的 expand 后到 → 列表只剩 A（或只剩后完成的那次）。
- **建议:** 后台 enrich 必须 merge，或带 generation token，过期 expand 不能覆盖更新的选择。

### 1.8 「跳过同名」整段空 chunk 会中止转换/压缩

- **文件:** `frontend/components/detail/batchRunners.ts`（约 153、289）
- **描述:** `chunk.length === 0` 时 `break` 而不是 `continue`。
- **失败场景:** 20 张，前 8 张输出已存在、chunk≈8 → 后 12 张根本不跑，成功/跳过计数被截断。
- **建议:** 仅在 `cancelRequestedRef.current` 时 `break`；空 chunk `continue`。

### 1.9 水印 / 缩放 / 拼接 / 富文本 / 宫格 / 分割 / 色板不走命名模板和冲突策略

- **文件:** `frontend/components/DetailView.tsx`

| 工具 | 约略行号 | 实际路径 |
|------|----------|----------|
| 水印 | 1695 | `{stem}_wm.png` |
| 缩放 | 1754–1765 | `{basename}_resized.{ext}`（basename **含扩展名** → `photo.jpg_resized.png`） |
| 拼接 | 1817 | `{firstStem}_stitched.{fmt}` |
| 富文本 | 1875 | `{name}.png` |
| 宫格 | 1582 | 共用 `output_dir`，引擎 `{stem}_01.png` |
| 分割 | 1638 | `{stem}_split/` |
| 色板 | 772 | `{stem}_palette_strip.png` |

- **描述:** 转换 / 压缩 / PDF / GIF 走 `buildOutputRelPath` + `resolveUniquePath`。上表工具写死文件名，也不调冲突解析。缩放还没 `stripExtension`。
- **失败场景:** 设置里的「自动重命名 / 跳过同名 / 模板」对这些页无效。两个目录的 `cat.png` 都会写成同一个 `cat_wm.png` / `cat_01.png`，后写覆盖先写。
- **建议:** 全部走同一套命名 + 冲突解析；缩放 `stem` 去掉扩展名。

### 1.10 skip 策略不把本批次已占用路径当冲突

- **文件:** `frontend/components/DetailView.tsx` `resolveUniquePath`（约 852–864）；批量 skip（约 896–914）
- **描述:** 单条 skip 传 `reserved: []`，只看磁盘 `exists`。本地 `reservedPaths` 在 skip 分支里不参与判断。rename 因为传了 `reserved` 是对的。
- **失败场景:** `a/cat.png` + `b/cat.png`，不保留目录结构，目标还不存在 → 两次都拿到 `IF_cat.png`，第二次覆盖第一次。
- **建议:** skip 把 `reservedPaths` 视为已存在；与 rename 共用 reserved 集合。

### 1.11 开始处理的锁在 `await` 之后才加上

- **文件:** `frontend/components/DetailView.tsx`（约 796–831）；`frontend/App.tsx`（约 348–350）
- **描述:** `handleStartProcessing` 用过期的 `isProcessing` 判断，`setIsProcessing(true)` 在 `await loadOutputSettings()` 之后。`DetailView` 按 `activeView` 换 key，切页不取消旧任务；`CancelProcessing` 只打 `current_task_id`。
- **失败场景:** 连点「开始处理」→ 两路并发写盘。处理中切工具页 → 旧 run 继续打后端，新页再开一轮，取消打到错误任务。
- **建议:** 用 ref + run id 加锁；切页/卸载调用 `CancelProcessing`，丢弃旧 run 结果。

### 1.12 富文本 `blocks[].path` 不走路径规范化

- **文件:** `backend/api/desktop_api.py` `_normalize_payload_paths`（约 149–164）；`backend/engines/richtext.py`（约 171–180、239–247）
- **描述:** 规范化只处理 `input_path` / `output_path` / `output_dir` / `image_path` / `input_paths` / `image_paths` / `images[]`。`blocks[].path` 原样 `Image.open`。缺图/坏图 `except: pass`，仍 `success: true`。高度 cap 16000 后循环仍按完整 plan 画，底部被裁也报成功。
- **失败场景:** 桌面语义下等于任意本地读；损坏图片块变成空白缝，用户以为导出完整。
- **建议:** 规范化递归 `blocks[].path`；缺图/超高返回错误或至少列入 `missing_images` 且 `success: false`（若选择宽松，UI 必须展示缺口）。

### 1.13 GIF 导出总像素预算按 1 帧算

- **文件:** `backend/engines/gif_splitter.py` `export_frames`（约 72–76）；`_assert_frame_pixel_budget`（约 823–837）
- **描述:** 导出调用 `_assert_frame_pixel_budget(animated.size, 1)`。倒放/压缩/缩放传真实 `frame_count`。`MemoryError` 被映射成 `GIF_EXPORT_FAILED`（`test_memory_budgets.py` 还固化了），调用方认 `GIF_MEMORY_LIMIT` 会漏。
- **失败场景:** 大图 × 很多帧，单帧未超 16MP、总像素远超 256MP → 照样导出。
- **建议:** 用 `len(frame_indices)` 或 `n_frames`；统一错误码。

### 1.14 PDF「加密」是 40-bit RC4，owner=user，权限全开

- **文件:** `backend/engines/pdf_generator.py`（约 175–177）；stdin `main()` 不转发 `user_password`
- **描述:** `encrypt=user_password`。ReportLab 把字符串当用户口令，owner 相同，默认强度 40，权限全开。UI 有密码框，没有实际保密能力。
- **失败场景:** 用户以为 PDF 受密码保护，文件可被轻易破解且打印/复制/编辑全开。
- **建议:** 明确 UI 文案（「打开口令，非强加密」），或改用 AES 并分开 owner/user；CLI 与 `process()` 参数对齐。

### 1.15 水印「居中」必崩

- **文件:** `backend/engines/watermark.py` `_paste_positions`（约 164–195）；`frontend/components/detail/WatermarkSettingsPanel.tsx`（约 13–16）
- **描述:** `"c"` 在 `POSITIONS` 里，不会回退到 `"br"`。随后用 `xs[position[1]]` / `ys[position[0]]` 当两位码。一位的 `"c"` → `IndexError`。无水印测试。平铺模式不走这段。
- **失败场景:** 选「居中」（非平铺）→ 预览空白；点应用 → `WM_FAILED` / `string index out of range`。
- **建议:** 把 `"c"` 映射为 `"cc"`，或按单字符特判；补居中/四角/平铺单测。

### 1.16 托盘创建失败仍会藏窗口

- **文件:** `backend/api/desktop_api.py` `close_request`（约 695–730）；`backend/infrastructure/tray.py`（约 41–82）
- **描述:** `background_running` 时无条件 `hide()`，不看 `ensure_tray()` 返回值。`_tray_icon` 在 `icon.run()` 之前就赋值；`run()` 异常被吞掉且不清引用。
- **失败场景:** 开「后台运行」再关窗口，pystray 起不来 → 窗口没了、托盘没有、进程和进程池还在。只能从任务管理器杀。
- **建议:** `ensure_tray()` 失败则 `runtime_quit()`；`icon.run()` 失败清 `_tray_icon` 并 `show()` 窗口。

## 二、MEDIUM

### 2.1 取消是协作式，架构文档仍写 kill

- **文件:** `backend/application/task_manager.py`；`docs/BACKEND_ARCHITECTURE.md` 约 92 行
- **描述:** 只设 flag；已在跑的 pool job 不会停。`future.cancel()` 只取消未开始的。README 这段与代码一致，架构文档仍写 `terminate()` / `kill()`、单任务 `multiprocessing.Process` + Queue。
- **建议:** 改文档；若产品需要「立刻停」，再设计可中断的 worker 协议，不要假装已经 kill。

### 2.2 水印预览先全分辨率合成再缩小

- **文件:** `backend/engines/watermark.py`（约 226–251、287–292）
- **描述:** 注释写「先缩小」；代码对大图先铺满 RGBA 再缩到 1100px。apply 在 `save_image.close()` 之后读 `.width/.height`。
- **失败场景:** 64MP + 平铺水印，预览即可分配数个全尺寸 RGBA 缓冲。
- **建议:** 真正先缩小再合成；关闭前把尺寸存进局部变量。

### 2.3 SVG 安全正则误伤内部引用

- **文件:** `backend/engines/_svg_ops.py` `_SVG_UNSAFE_PATTERN`（约 22–33）
- **描述:** `\bxlink:href\s*=` 连 `#icon` / `<use>` 都拒。常见图标 SVG 转换直接失败。同时 CSS `url(...)` 外连漏检（见 1.4）。
- **建议:** 只拦截 `file:` / `https?:` / `//` 形式的 href，允许片段引用。

### 2.4 转换「覆盖源文件」仍走全局冲突策略

- **文件:** `frontend/components/detail/batchRunners.ts`（约 122–126）
- **描述:** 改扩展名时 `resolveUniquePath(overwritePath)`。全局 skip/rename 会跳过或改成 `photo_01.jpg`，而不是替换 `photo.jpg`。同扩展名覆盖才是真覆盖。
- **建议:** 覆盖源文件路径跳过全局冲突解析，或 UI 标明「仅同格式覆盖」。

### 2.5 取消项被算进成功

- **文件:** `frontend/components/batchHelpers.ts`（约 89–117）；`frontend/components/batchHelpers.test.ts` 固化了该行为
- **描述:** `[PY_CANCELLED]` 不加 `failed`；`summarizeBatchProgress` 用 `settled - failed`。
- **失败场景:** 3 成功 + 1 取消 →「成功 4/4」。
- **建议:** 成功数只用 `item.success === true`；文案区分取消。

### 2.6 默认输出目录是源目录

- **文件:** `frontend/components/DetailView.tsx`（约 619–623、823–828）
- **描述:** 没选输出文件夹且设置为空时，`effectiveOutputDir` = `files[0].source_root`。提示「请选择输出位置」，点开始仍往源目录写。叠加上面的硬编码文件名，容易覆盖原图。
- **建议:** 无显式输出目录时拒绝开始（覆盖源文件模式除外）。

### 2.7 文件夹还在展开就点开始

- **文件:** `frontend/components/FileDropZone.tsx`（约 703–716）+ `DetailView.tsx` 开始处理
- **描述:** 乐观列表可能把目录路径当成文件，或只有部分文件。无「展开中」锁。
- **建议:** expand 完成前禁用开始，或开始时等待当前 expand generation。

### 2.8 GIF 倒放走弱路径

- **文件:** `backend/engines/gif_splitter.py` 倒放 vs 变速/压缩/缩放
- **描述:** 倒放用 `_extract_gif_frames`（常见 `P` 模式、无 disposal）。保存还强制 `transparency=255`。测试只用实心 RGB 帧。
- **失败场景:** 分帧调色板 + disposal=2 的动画倒放后变色或打洞。

### 2.9 动画 WebP 恒 `lossless=True`

- **文件:** `backend/engines/gif_splitter.py` `_save_webp`（约 699–714）
- **描述:** 同时传 `quality` 和 `lossless=True`。质量滑条无效，文件偏大。

### 2.10 `strip_metadata` 对 WebP / fallback 是空操作

- **文件:** `backend/engines/compressor.py` WebP 与 fallback 分支
- **描述:** JPEG 有剥离实现；PNG 走 oxipng StripChunks；WebP/TIFF/BMP 接收该标志但不使用。
- **失败场景:** 带 GPS EXIF 的 WebP，勾选剥离后输出仍含 EXIF。

### 2.11 `build_gif` 无像素预算

- **文件:** `backend/engines/gif_splitter.py`（约 272–322）
- **描述:** 其它 GIF 操作走 `_assert_frame_pixel_budget`；从静图合成 GIF 把每张载入 RGBA 再 pad 到 max(w)×max(h)，无帽。

### 2.12 非法 GIF `frame_range` 静默导出全部帧

- **文件:** `backend/engines/gif_splitter.py`（约 639–655）
- **描述:** 解析失败或 `step=0` 回退 `range(total_frames)`。范围还是 0-based。

### 2.13 进程池与水印无测试

- **文件:** `backend/tests/test_task_manager.py` 强制禁用进程池；`backend/tests/engines/` 无 watermark
- **描述:** 引擎有 converter/compressor/gif/grid/pdf/new_tools（splitter/resizer/palette/stitcher/richtext）。pool 增长、取消、跨进程错误、水印居中全部未覆盖。这是 1.6 / 1.15 能进 2.2.0 的原因。

### 2.14 打包未收集原生 wheel 二进制

- **文件:** `backend/packaging/release_builder.py`（约 84–128）；`backend/tests/test_release_builder.py` 只断言 frontend dist 与 `ico.png`
- **描述:** 仅 `--hidden-import` / `--collect-submodules`。`pillow_heif`、`resvg_py`、`mozjpeg_lossless_optimization`、`imagequant`、`oxipng`、Tcl/Tk 常带 DLL/数据，分析器容易漏。
- **失败场景:** 安装包里 HEIC/AVIF/压缩增强/SVG 光栅化失败，`uv run` 正常。
- **建议:** 对上述包 `--collect-all` / `--collect-binaries`；发版前做安装包冒烟。

### 2.15 `npm run dev` 关窗口不杀 Vite

- **文件:** `scripts/dev.mjs`（约 127–129）；对比 `scripts/dev.py`（约 202–206）
- **描述:** 默认 `package.json` `"dev"` 走 JS 启动器。backend `exit` 只把 `backendProcess = null`。Python 启动器会拆整棵进程树。
- **失败场景:** 关窗口后 5173 仍占用，下次启动换端口。

### 2.16 窗口记忆不钳虚拟屏
