# ADR-003：8 位调色工作空间与精度声明

- 状态：已采纳
- 日期：2026-11-17
- 关联：STUDIO-01、STUDIO-02、CORE-02、PRO-01

## 背景

PRD 要求专业调色"优先保持 16 位或浮点工作中间数据"，同时要求"无法提供高位深能力时应标注为 8-bit 调色模式，避免过度保证不出色带"。现有管线的事实是：

- 输入经 `internal/codec.Open` 归一到 sRGB；有 ICC 的源经 LCMS/WASM 转换。
- 高位深输入（NRGBA64/RGBA64/Gray16）在几何路径保留位深（`internal/codec/geometry.go`），但调色链按 8 位处理。
- 现有 ICC 回归覆盖：CMYK 输入、无 ICC 容器的导出、HDR10 AVIF 映射、PNG cICP。

## 决策

调色引擎采用**明确标注的 8 位工作空间**，并把曝光放在线性光中计算：

- 曝光（EV）在 sRGB↔线性光之间往返，只在这一步使用线性值。
- 其余参数（对比、明暗、色阶、曲线、HSL、饱和度、白平衡偏移）在 sRGB 编码值上计算。
- 页面固定显示"当前为 8 位调色模式"的告警，不得在文案中出现"专业级高精度"之类承诺。

## 理由

1. 在编码值上做曝光是错的（一倍曝光应让线性值翻倍），但在线性光上做全部参数会让对比与曲线偏离用户对滑块的常识预期；分区处理是唯一既不撒谎又符合直觉的方案。
2. 8 位工作空间是现有管线的真实上限。把它写进页面，比提供一个"看起来支持 16 位"的开关更可信。
3. 调色是**纯函数**：给定源图与参数集，输出确定。`engine.Grade` 对中性参数直接返回源图，因此反复切换参数不会累积量化误差——这一条已由 `TestGradeNeutralIsPixelIdentical` 与 `TestGradeIdentityReturnsTheSource` 固定。

## 后果

- 曲线使用 Fritsch–Carlson 单调 Hermite 插值，而不是 Catmull-Rom：过冲样条会让渐变出现反向台阶（`TestCurveIsMonotone` 固定该行为）。
- LUT 支持 3D `.cube`，用三线性插值；解析器拒绝样本数与声明尺寸不符、NaN/Inf 分量、1D 表与越界尺寸（`TestLoadLUTRejectsBadInput`）。
- 若将来引入 16 位/浮点工作空间，必须：新增 ADR、提供色带测试样本、在能力快照中新增独立行，并保留 8 位路径作为降级选项。

## 未采纳的方案

| 候选 | 未采纳原因 |
|---|---|
| 全程线性光处理 | 对比与曲线会与用户对滑块的预期脱节，且需要浮点缓冲，管线改动超出本次范围 |
| 提供"16 位"开关但内部仍 8 位 | 属于虚假声明，PRD 明确禁止 |
| 引入第三方调色库 | 无 PoC 证据表明其精度、许可或包体积优于当前纯 Go 实现 |
