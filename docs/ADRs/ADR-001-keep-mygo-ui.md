# ADR-001：保留 MyGo + Lobe MyGo 作为界面栈

- 状态：已采纳
- 日期：2026-11-17
- 关联：M0-01、M0-08、ADR-008（PRD §12.3 TECH-03）

## 背景

PRD 要求"Go 原生优先"，同时明确该表述的含义是图像处理、任务调度、预览/导出契约与常规流程由 Go 承担，不等于必须重写界面层。仓库基线 v3.1.0 已有 14 个入口、1–16 张拼图、侧栏拖拽排序、设置迁移与六平台构建，全部建立在 `github.com/egoist/mygo` 与 `github.com/lobehub/lobe-mygo` 之上。

## 决策

保留现有 MyGo + Lobe MyGo 原生控件栈。不引入 Wails、Fyne 或 WebView 壳，不把界面重写列为本次任何任务的前置条件。

## 理由

1. 现有界面已有回归覆盖（`internal/ui/*_test.go` 共 20 余个用例，含 `ui.NewTester` 逐页渲染、深色模式、栅格对齐、拖拽换序、设置往返）。
2. 换壳会同时替换控件语义、焦点模型、DPI 行为与无障碍树，回归成本远高于本次要交付的增量功能。
3. MyGo 的生命周期约束（`ui.Context` 不跨帧保存、后台结果经 `Window.Update` 发布）已被现有代码正确实现，新增页面沿用同一模式即可，无需新机制。

## 后果

- 新增 11 个页面必须遵守既有生命周期约束：只保存数据、控件状态与 `ui.Handle`，不保存跨帧 `Element`。
- 界面层不直接调用第三方图像库；所有像素操作经 `internal/engine`。
- 若将来出现实测瓶颈（如 8K 画布拖动），需另起 ADR 并附冷启动、常驻 RSS、拖动延迟的前后对照，不得以"Go 更原生"为理由。

## 未采纳的方案

| 方案 | 未采纳原因 |
|---|---|
| Wails | 系统 WebView 仍有独立进程与内存占用，不能宣称纯原生；迁移成本落在已经稳定的页面上 |
| Fyne | 复杂画布、富文本排版与动画时间轴的可达性未验证，替换即等于重做创作类页面 |
| 自绘新控件栈 | 与 MyGo 的能力重复，且会失去现有焦点、无障碍与测试工具 |
