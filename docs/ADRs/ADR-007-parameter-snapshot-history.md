# ADR-007：编辑会话使用参数快照历史，而不是像素版本栈

- 状态：已采纳
- 日期：2026-11-17
- 关联：CORE-03、EDIT-01…03、UI-02、SYS-03

## 背景

PRD 的 SYS-03 要求"源图保持只读；编辑保存操作描述及参数快照；预览使用低分辨率缓存；最终导出重新读取源图运行同一算法"。同时强调"不默认将大图每个版本保存成 PNG"。

现有 `internal/batch/session.go` 已有 `runID` 与输入身份机制，但它是**批量任务会话**，不是操作树 Undo/Redo。两者混用会让"删除输入行"与"撤销一次裁剪"共享同一状态，语义混乱。

## 决策

新增 `internal/history`：一个有界、泛型的参数快照栈。

- 每个页面持有自己的 `Stack[T]`（`EditTool` 存 `editSnapshot`，`GradeTool` 存 `engine.GradeParams`，`AnnotateTool` 存 `[]engine.AnnotateMark`）。
- `PushIfChanged` 用页面提供的等价函数去重，所以"什么都没改的一帧"不会增长历史。
- 上限默认 100 步（各页按需设为 40…60），超出丢弃最旧项。
- 新编辑会截断 redo 分支。
- 页面渲染始终从"源图 + 当前参数"重算，历史只存参数，不存像素。

## 理由

1. 参数快照的内存成本是几个浮点数，而像素版本栈是每步一份位图；后者在 8K 图上必然触发 OOM 风险（R-02）。
2. "从源图重算"保证预览与导出一致：同一参数集走同一算法，只有分辨率策略不同。
3. 页面级历史与批量会话解耦，"删除输入行"不会意外撤销一次调色。

## 后果

- `internal/history` 有 6 个单元用例覆盖 undo/redo 行走、redo 截断、边界淘汰、去重入栈、零值回退与空栈语义。
- 基础编辑页把全部参数打包成可比较结构体，`record()` 在每帧末尾调用；调色页同理。
- 标注页存整份标注列表（每个标注是 4 个浮点 + 标签），而不是像素。

## 未采纳的方案

| 方案 | 未采纳原因 |
|---|---|
| 每步保存一张 PNG | 内存与磁盘成本随步数线性增长，违反"不默认保存大图版本" |
| 复用批量会话的 `runID` 做 Undo | 批任务身份用于防止旧结果回填，语义与操作历史不同 |
| 无界历史 | 长时间拖动滑块会无限制增长内存 |
