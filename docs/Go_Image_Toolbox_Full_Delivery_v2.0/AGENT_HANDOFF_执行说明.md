# 开发 Agent 交接说明（建议与整套资料一起提供）

## 任务目标

对现有 Go 图片工具箱**增量扩展和修复**。以 `01_产品需求/PRD_v2.0_完整产品需求.md` 为产品基线，其余文档作为 UX、技术、AI 和测试补充；不要直接把本交付包当作现有仓库源码。

## 本轮范围

允许：基础处理、创作排版、专业图像、动态素材、可选 AI 高清放大，Go 实现优先、可选 NCNN/Vulkan 推理引擎。保留原有功能兼容性，包括历史“转 PDF”入口（冻结不扩展）。

禁止：OCR、文档扫描/文档新增功能、新增开发者工具/CLI/API、跨工具批处理管理中心、独立图片管理/去重、强制线上图片处理、无依据的全量重写。

## 已确认基线与本次交接

先读 [M0 仓库适配基线](04_实施与测试/M0_仓库对齐与增量实施基线.md)。本次仅修订计划，不授权创建分支、提交、推送或发布。保留 Go 1.27.3、MyGo + Lobe MyGo、CLI、六平台构建与签名更新链。首批任务是兼容回归和共享对比/会话的增量方案，不是全量重写。

## 执行规则

1. **先核对已有 M0 基线**。复核当前 commit 的差异，补充性能与原生交互证据；不要重新把所有入口标为未知。维护唯一需求矩阵，避免复制后状态分叉。
2. **不要盲目替换依赖**。对 Go 图片编解码器、ICC、APNG、动画 WebP、GIF、文字、图标等先做小范围 PoC 并锁版本。`kovidgoyal/imaging` 上游要求 Go 1.26，`bild` 上游要求 Go 1.25；评估和当前项目的兼容性。
3. **所有文件输出必须保留原始图片**。采用受控临时文件、结果复核与可靠提交；失败/取消不能产生假成功输出。
4. **先做 P0 后做 P1**。每个 PR 关联需求 ID、测试结果和故障路径。对老入口不能做无测试的大规模 UI/数据迁移。
5. **AI 单独实现和验收**。Go 调度可信 NCNN 原生子进程；首选经检查的 Real-ESRGAN-ncnn-vulkan。Upscayl AGPL fork、模型和子模块各自做许可证核查。AI 模型不能默认混入基础安装包。
6. **性能以实验为准**。统计全进程内存、冷启动、首屏响应、AI 端到端、显存；同引擎同模型同 GPU 比较，不得仅因采用 Go 就宣称推理更快。
7. **定期交付可运行增量**。每个 issue 须包含源码变更、使用说明、测试、UI 证据、兼容信息、回滚说明。没有通过测试的功能不可在产品中宣称可用。

## 第一轮必须输出的文件

- 本包 `04_实施与测试/M0_仓库对齐与增量实施基线.md`：已提供源码现状，后续增补证据。
- 本包 `01_产品需求/需求追踪矩阵.md`：维护单一状态表，不另行复制。
- `docs/ADRs/*.md`：仅为实际差异补充决策；GUI、编解码、ICC 和动画先复用，AI 模型另行审查。
- `docs/benchmarks/baseline.md`：基线设备、图像哈希、P50/P95、全进程内存。
- `docs/licenses/COMPONENTS.md`：构建使用的每个外部依赖和模型。
- `docs/roadmap_issue_plan.md`：把 M1–M6 子项拆为真实可实施 issue，列依赖和验收条件。

## 准入门槛

在未获得**实际项目源码**之前，不得声称 PRD 中的任务已在项目中实现；不允许仅做演示页面就认为已经具备图像编码/保存能力。必须优先证明输入可以导入、算法实际运行、输出可重新打开、原图不受损。
