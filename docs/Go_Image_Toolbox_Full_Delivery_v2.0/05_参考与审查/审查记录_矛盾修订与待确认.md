# 文档完整性复审：冲突、修订、未决事项

> **2026-11-17 仓库适配修订**：软件基线为 `v3.1.0`，不是本包版本号。先读 [M0 仓库对齐与增量实施基线](../04_实施与测试/M0_仓库对齐与增量实施基线.md)。本次只优化规划；源码核查、历史测试、人工验收和性能实测分别记录。

> 本记录复核：`开发规范 v1.0` 与 `PRD v2.0`，以较晚且明确用户范围的 PRD v2.0 为产品基线。凡技术文档与 PRD 有差异，均应标记并采用最新需求，不允许默默取舍。记录日期：2026-11-16。

## 1. 审查方法与限制

- 输入：用户提供的现有 14 功能侧栏截图、后续范围指示、两份完整原始 Markdown 文档。
- 方法：逐节检查范围、优先级、模块归属、技术术语、对 AI/Go 性能的假设、输入输出与测试一致性。
- 原交付限制：当时未取得源码。2026-11-17 已补充本地源码、依赖、历史回归及发布证据；本轮仍未测量性能、GPU 或原生交互，不能据此宣称 PRD 全部验收。

## 2. 需要优先遵循的结论

| 审查项 | 旧文档/潜在误解 | 统一后的规则 |
|---|---|---|
| REV-01 优先级 | v1 某些功能使用 P0/P1 混标 | PRD 按主模块给等级，已有功能维稳可 P0、增强 P1 |
| REV-02 批量范围 | “不做批量管理”可能误伤批量水印 | **不做独立中心**，单工具内多图处理保留 |
| REV-03 旧 PDF | 用户说不要文档功能 | 冻结旧“转 PDF”，不扩展、不未经批准删除 |
| REV-04 富文本制图 | 可能被误解成 Word/PDF 编辑器 | 仅将富文本排版成图片，非文档生产 |
| REV-05 图标生成 | 可能演变成开发者资源导出中心 | 只做通用 ICO/Favicon/PNG 图标生成，不建设开发者工具族 |
| REV-06 视频帧提取 | 可选 FFmpeg 可能被写成默认依赖 | P2，按需安装，缺失时核心功能不退化 |
| REV-07 AI 能力 | “Upscayl 支持”可能被误解成复制主程序 | 仅功能对标，优先独立 Go + MIT NCNN 适配 |
| REV-08 AI 性能 | Go 替换 Electron 被直接等价为推理更快 | 仅能假设宿主开销较低，模型实际推理需同配置实测 |
| REV-09 AGPL/MIT | 引擎、模型、发行许可混为一谈 | 每一个引擎、权重、依赖分别审核，不能只核主 LICENSE |
| REV-10 编码格式 | README 说“支持”可能只有 decode | 能力矩阵必须区分 decode/encode/animated/ICC/Alpha |
| REV-11 ICC 高级调色 | 原生 Go 8-bit 处理被当成专业完整精度 | 先做 ICC/高精度 PoC，未通过只显示受限模式 |
| REV-12 GIF 动画 | 直接用局部帧当整帧 | 必须合成完整帧并正确处理 disposal、offset、时长和 loop |
| REV-13 性能数字 | 2s/150MB/250ms 等被误看成已实现 | 全部只是目标，M0 之后实测与 ADR 才冻结门槛 |
| REV-14 前端重构 | Go 原生优先被误读成必须重写所有 UI | Go Core 优先、GUI 根据当前成熟度决定，严控重写成本 |
| REV-15 需求混用 | 同一底层画布可能被做多套 | 共享 Canvas、Operation、Preview、Export；产品入口语义独立 |
| REV-16 安全遮挡 | 模糊/马赛克被误写成永久脱敏 | 不透明覆盖合成到最终像素才称“安全遮盖” |
| REV-17 源文件安全 | `os.Rename` 被当作 Windows 通用原子覆盖 | Windows 替换/同名冲突需专项事务实现和测试 |

## 4. 现阶段不可证实的内容

- 原有 14 个入口未被现有回归覆盖的子功能与原生交互表现；已确认源码范围见需求矩阵。
- 目标设备上的 GUI 响应、资源占用与长期稳定性；Go 1.27.3 和 MyGo 已确认。
- 旧压缩器是否比候选方案慢，以及在具体图片类别上的压缩效果差距。
- `kovidgoyal/imaging` 或 `bild` 当前代码是否与你现有 Go 版本兼容。
- Real-ESRGAN 模型在你的电脑/目标用户电脑上的具体速度、显存占用和质量排名。
- 所有第三方模型的商业分发权利与当前版本许可证结论。
- 包中的性能门槛是否对所有支持硬件都可实现。

## 6. 开发交付与变更控制

本包是**文档基线**，不是实现仓库。把它交给代码 Agent 时，应首先执行 M0，更新需求追踪表及 ADR。在开 PR 之前完成仓库现状核查；每个 PR 对应明确需求 ID、E2E、风险和回滚。禁止因新增图片创作需求而自行恢复 OCR、文档功能、跨工具批量管理或开发者工具。
