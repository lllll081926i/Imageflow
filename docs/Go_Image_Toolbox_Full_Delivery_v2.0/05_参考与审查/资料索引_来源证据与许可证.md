## 1. 证据等级使用方法

- **A｜由用户确认**：截图显示的 14 个功能入口、明确要排除的范围、希望 Go 原生优先和纳入 Upscayl 类增强。
- **B｜由上游文件支持**：公开代码中存在的功能、依赖声明、CLI 参数、项目 LICENSE。
- **C｜产品建议**：PRD 和配套设计提出的功能、优先级、用户流程、性能目标，不能当成已经实现。
- **D｜待补证**：未覆盖的格式子能力、性能、原生交互、GPU 兼容、模型分发权利、工作量。Go 版本、GUI 和现有实现已由源码确认，见 M0 基线。

本交付包没有当前图片工具箱仓库、可运行包或 `go.mod`，因此未执行真实代码审计和性能跑分。

## 2. 已确认原始需求

**截图的 14 个入口**：格式转换、尺寸调整、图片裁剪、宫格切图、图片布局、图片拼图、长图拼接、批量水印、色彩提取、图标生成、转 PDF、GIF 工具、富文本制图、图片压缩。

**本轮产品范围**：基础处理、创作与排版、专业图像、动态与素材、Upscayl 类 AI 高清放大。原有“转 PDF”不要求删除但不扩展，文档功能冻结。

**本轮排除**：OCR、文档扫描、表格/文档处理、开发者工具、跨工具批量管理与文件管理中心。

**技术偏好**：Go 原生优先，必要时使用经验证的 Go 库或独立原生程序。UI 框架不强制在缺少源码时推倒重做。

## 5. 许可证审查登记模板

| 字段 | 说明 |
|---|---|
| Component | 库/模型/二进制/字体名称 |
| Repo + commit | 上游仓库与确切版本 |
| Source URL | 源文件或发行页 |
| SHA256 | 真实发布文件摘要；下载后填入 |
| License ID | SPDX 或实际许可证名称 |
| Dependency licenses | 原生依赖与子模块授权 |
| Model rights | 模型权重使用/修改/分发许可 |
| Modification | 是否作出修改，是否有对应源码义务 |
| Redistribution approved | 发布责任方核准状态；未经批准默认 false |
| NOTICE / attribution | 需要随发行物提供的声明 |
| Verification owner | 技术/法务审核人 |

**不能将本表的项目许可证直接作为发布物整体合规结论**；同一发行包中每个模型和依赖均独立核对。

## 6. 未完成但必须进行的核查

1. 复核 M0 与当前仓库差异，保留 MyGo 和既有编解码链，按增量实施。
2. 以真实项目版本测试每个编解码器的 decode、encode、Alpha、ICC、animation、metadata 能力。
3. 固定 Go 1.27.3 与已锁定依赖；不存在升级到 1.25/1.26 的任务。替换库前提交能力、许可与性能对照。
4. 取得合法权重，核对每个 NCNN 模型和 Real-ESRGAN 引擎的兼容性。
5. 固定 benchmark 设备、样本与压缩质量指标，禁止无证据的“更快”“更小”宣传。
6. 评估旧“转 PDF”入口位置与用户数据兼容，不在本轮添加文档类新功能。
7. 为专业调色准备 ICC/16-bit 标准图和对照工具，建立数值验收。
8. 为 GIF disposal 2/3、APNG/动态 WebP 准备权利清楚的复杂动画数据。
