## 1. 产品概述

### 1.1 一句话定位

以 **高性能、低资源占用、纯本地处理、功能专业但操作简单** 为核心的 Windows 桌面图片工具箱：用户不必打开大型编辑器，即可完成图片转换、编辑排版、专业调色、动图制作和 AI 高清放大。

### 1.2 问题定义

- 常规图片任务分散在多个小工具，格式兼容、预览和输出规则不一致。
- 许多工具只提供参数滑块，缺少对结果质量、文件大小和错误情况的明确反馈。
- 繁重桌面框架与不必要的后台组件增加启动、内存与部署成本。
- 有些高频需求（拼接、图片标注、GIF 帧操作、颜色分析）无需大型图像创作软件，但独立工具切换成本高。
- AI 放大具有价值，却不应强迫所有用户下载 GPU 推理组件和模型。

### 1.3 产品原则（按优先次序）

1. **保护原始图片**：默认不覆盖；写入成功可验证，失败/取消不留伪结果。
2. **常用任务直达**：普通用户 3–5 个清晰步骤完成“导入—调整—预览—保存”。
3. **结果可预期**：输入格式、透明度、动画、多帧、ICC、压缩后的质量/体积都要有真实反馈。
4. **先 Go、后依赖**：优先使用 Go 标准库和合理规模的纯 Go 库；原生扩展按需装载。
5. **离线优先**：普通工具完全本地运行；无账号、无远程图像上传前置条件。
6. **不做全能图像编辑器**：不追求 PSD、复杂矢量编辑、RAW 专业冲印、视频剪辑和文档生产。
7. **渐进增强**：基础安装包保持完整可用；AI、视频、特种编解码以可选组件形式提供。

### 1.4 产品目标（Outcome）

| 目标 ID | 目标 | 度量方法 | 第一正式版建议阈值 |
|---|---|---|---|
| GOAL-01 | 高频图片任务顺利完成 | 固定任务集的用户端到端成功率 | ≥ 95%，不计人为取消 |
| GOAL-02 | 不损坏已有图片 | 覆盖/取消/崩溃/磁盘空间不足测试 | 未经明确确认的源文件修改 = 0 |
| GOAL-03 | 常规交互响应流畅 | 普通图片拖动滑块与低清预览延迟 | 目标 P95 ≤ 250 ms，需 M0 校准 |
| GOAL-04 | 内存和安装成本可控 | 空闲内存、峰值内存、基础安装包体积 | 建立当前产品基线，核心包不含 AI 模型 |
| GOAL-05 | 动画与色彩输出正确 | GIF disposal、Alpha、ICC、方向回归 | 关键数据集全部通过 |
| GOAL-06 | AI 放大有明确效用且可关闭 | 模型加载、GPU 失败恢复、结果对比 | 独立安装/卸载；无组件时核心功能 100% 可用 |

阈值为拟议产品验收目标，不是已测数据；相关硬件、图片数据集和 UI 框架须先在 M0 固定。

### 1.5 非目标（明确不做）

- OCR、文档扫描、透视校正文档、表格识别、可搜索 PDF、PDF 拆分合并及其他文档工作流。
- 新增 CLI、开放 API、CSS Sprite、Base64 工具、开发者资源自动生成中心。现有 `imageflow-batch`、`imageflow-icon` 保留兼容与回归。
- 跨工具的可视化批处理流程、文件管理中心、自动整理相册、去重、目录监控。
- 在线素材库、账号云同步、社交分享平台、用户图片上传后台。
- Photoshop 级复杂图层、PSD 互通承诺、完整 RAW/CMYK 印前流程、视频编辑/录屏套件。
- AI 文生图和云端 AI 服务作为必要功能。

### 1.6 旧“转 PDF”兼容策略

截图中第 11 个现有入口为“转 PDF”。鉴于“文档相关不再开发”，采取 **保持现状、冻结迭代、不纳入新导航重点、不得直接删除原有用户能力** 的策略。若以后正式移除，需要另起迁移决策，包括历史功能使用情况、入口重定向和旧版兼容；本 PRD 不批准移除。

## 2. 目标用户与关键场景

### 2.1 用户角色

| 角色 | 典型场景 | 核心诉求 | 主要入口 |
|---|---|---|---|
| 日常用户 | 上传网站照片、调整尺寸、裁剪头像 | 少设置、一次做对 | 转换、缩放、裁剪、压缩 |
| 内容创作者 | 社媒拼图、长图、图文卡片、表情包 | 模板、好看、输出方便 | 拼图、布局、文字制图、标注、GIF |
| 轻专业用户 | 调色、滤镜、分析压缩损失 | 可控参数和真实画质对比 | 调色、滤镜、直方图、图片对比 |
| 动漫/素材用户 | 动图编辑、头像图标、点阵素材 | 动画准确、细节清晰、兼容性好 | GIF、图标、像素画、色彩提取 |
| 本地 AI 用户 | 放大低分辨率照片和插画 | GPU 利用、模型质量、低宿主开销 | AI 高清放大 |

### 2.2 核心用户故事

- **US-01**：作为普通用户，我希望拖入一张截图并压缩到平台限制以内，在能看清文字的前提下得到尽量小的文件。
- **US-02**：作为内容创作者，我希望选几张图片快速自动拼图，拖动重排并导出适合社交平台的尺寸。
- **US-03**：作为图片爱好者，我希望对比处理前后像素细节和色彩变化，以确定是否值得保存。
- **US-04**：作为动图用户，我希望拆出 GIF 帧、改播放速度、删帧、循环并保存，结果不闪烁、不变黑。
- **US-05**：作为动漫素材用户，我希望将图片变为严格黑白的 400×300 点阵图，并控制抖动算法。
- **US-06**：作为本地 AI 用户，我希望检测本机 GPU、安装兼容模型并对单张图片放大；即使没有 AI 环境，其他图片工具仍可用。
- **US-07**：作为注重隐私的用户，我希望对截图中的敏感信息做不可逆不透明覆盖，且不保留位置等无关元数据。

### 2.3 关键旅程（Service Blueprints）

**旅程 A：压缩截图**：首页/快捷入口 → 导入 → 显示尺寸/透明度/体积 → 选择“指定大小” → 看到目标达成状态与文字清晰度对比 → 导出。若无法达标，应建议允许降低分辨率或转换格式，而非静默失败。

**旅程 B：多图拼图**：导入 1–16 张 → 自动给出布局模板 → 选择模板 → 调整每格取景与间距 → 选择导出尺寸 → 保存，且可返回继续修改。

**旅程 C：GIF 编辑**：导入 GIF → 解析完整帧及 disposal → 播放/暂停 → 重排与修改帧时长 → 预览与原图对照 → 优化导出 → 验证最终循环及透明区域。

**旅程 D：AI 放大**：导入 → 环境探测（GPU/引擎/模型）→ 选择模型和倍率 → 局部比较 → 运行 → 进度/取消 → 输出质量对比；无 GPU 或损坏模型时可进入说明与修复页，不影响其他工具。

## 3. 需求范围、优先级与版本包

### 3.1 优先级定义

| 级别 | 定义 | 发布策略 |
|---|---|---|
| **P0** | 影响基本稳定性、现有高频功能或全局正确性的必需能力 | 不满足则不发布核心版 |
| **P1** | 与本次产品定位强相关的新功能或现有增强 | 主线版本逐批发布；未开发不冒充支持 |

| 高级图片比对 | 图片对比 | 所有处理页均可使用对比组件 | 不同工具不能各写对比指标 |

## 4. 产品信息架构与导航

### 4.1 建议侧栏层级

```text
首页
├─ 常用（用户可固定）
├─ 最近使用（仅保存工具与参数，不自动保存用户图片）
├─ 基础处理
│  ├─ 格式转换  尺寸调整  图片裁剪  图片压缩  基础编辑
├─ 创作与排版
│  ├─ 宫格切图  图片布局  图片拼图  长图拼接
│  ├─ 批量水印  富文本制图  图片标注  截图美化
├─ 专业图像
│  ├─ 专业调色  滤镜效果  图片对比  图像分析  位图矢量化（高级）
├─ 动态与素材
│  ├─ GIF/动图  图标生成  色彩提取  像素画/点阵图
│  ├─ 表情包制作  视频帧提取（可选）  素材背景生成（高级）
└─ 智能增强（组件可用时展示）
   └─ AI 高清放大  [后续可选：智能抠图]

设置
├─ 外观与语言  性能与缓存  导出偏好  编解码能力
├─ 模型与组件  隐私与元数据  关于与许可证
└─ 已有旧功能（如“转 PDF”）：根据现有用户习惯可保留原位或放入其他工具
```

侧栏默认只展开当前分组；可收藏常用入口；支持搜索工具名称和同义词（例如“改大小”“放大”“去背景”“打码”）；搜索**工具**不等于检索用户本地图片资源，不做文件管理能力。

### 4.2 页面结构

- **首页**：搜索、固定常用工具、最近使用、拖入图片快捷推荐。推荐工具只参考本地文件类型和用户操作，默认不上传、不做内容语义识别。
- **标准编辑页面**：左侧或中部预览工作区、右侧参数面板、顶端文件信息和撤销/重做、底部导出栏。窗口宽度不足时参数栏收起，画布优先。
- **画布型页面**：对象列表/层级、中央画布、属性栏、对齐吸附提示、尺寸与导出状态。
- **动图型页面**：播放器、时间轴/帧列表、单帧属性、播放控制与导出设置。
- **AI 页面**：硬件/引擎状态、模型选择、输入与局部对比、任务进度、输出。

### 4.3 全局交互状态机（UI-01）

`空状态 EMPTY → 文件加载中 LOADING → 已就绪 READY → 预览计算中 PREVIEWING → 可导出 EXPORT_READY → 导出中 EXPORTING → 成功 SUCCESS`。

异常分支：`LOADING/ PREVIEWING/ EXPORTING → ERROR / CANCELLED`；错误可重试，取消回到上一个有效编辑会话。AI 页面多两个状态：`COMPONENT_MISSING`（组件缺失）与 `GPU_UNAVAILABLE`（设备不可用）。导出状态不得依赖单纯“进度条到 100%”，应以生成文件实际校验为准。

### 4.4 必须统一的交互（UI-02）

- 拖入文件、文件选择器；静态图片页支持剪贴板粘贴图像（若桌面壳允许）。
- 支持“适应窗口/100%/放大/缩小/平移”；高清像素比较锁定两图缩放与对应坐标。
- 参数修改默认不破坏原图，撤销/重做至少在当前会话可用；恢复默认与取消编辑逻辑明确。
- 导出选项至少包含路径、文件名、格式（由真实编码能力决定）、质量或压缩级别（仅格式有效时）、透明背景策略、元数据策略。
- 实时预览与最终导出语义一致：预览可降分辨率，裁剪框几何比例、字体排布、颜色计算必须在容差内保持一致。
- 输出路径同名时显示“另存 / 覆盖（确认） / 取消”，默认“另存”。
- 出错时显示清晰的原因和操作建议，不仅弹“失败”。耗时操作有取消按钮。

### 4.5 建议键盘和无障碍（UI-03）

| 操作 | 快捷键建议 | 说明 |
|---|---|---|
| 打开图片 | Ctrl+O | 桌面平台可用时 |
| 保存/导出 | Ctrl+S / Ctrl+Shift+S | 以“另存”语义优先，不默默覆盖 |
| 撤销/重做 | Ctrl+Z / Ctrl+Shift+Z | 当前会话生效 |
| 适应窗口 / 100% | Ctrl+0 / Ctrl+1 | 避免和输入框焦点冲突 |
| 取消操作 | Esc | 取消拖动/关闭弹层，长任务须明确二次动作 |
| 复制结果 | Ctrl+C | 预览结果可复制时，支持标准位图剪贴板 |

必须有焦点样式、键盘可操作的参数控件、色彩之外的状态反馈、文字标签/Tooltip，支持 Windows 显示缩放 100%–200% 的正常布局；快捷键须与现有项目冲突检测后确定。

## 5. 全局数据、图像与导出规则

### 5.1 图片信息与能力检测（SYS-01，P0）

导入后展示：真实格式、宽×高、帧数（动态图片）、输入体积、Alpha、位深（能可靠识别时）、方向、ICC 配置（若可识别）、元数据存在与否。文件类型以文件头检测与有效解码为依据，扩展名仅作显示辅助。

界面应基于 `CodecCapability` 运行时结果显示读/写/动画/Alpha/ICC 能力；**禁止对尚未测试的 AVIF、HEIC、JXL 或动态 WebP 写入显示“完全支持”。** 插件不可用时展示原因和可选解决路径。

### 5.2 色彩/透明度与方向（SYS-02，P0）

- 归一 EXIF Orientation，不在再次输出时重复旋转。
- 透明图片转不透明格式时，必须提供显式的背景填充颜色（默认白色，用户可改）。
- 不同操作对 Alpha 的行为一致，半透明边缘不得变黑/变白。
- 专业调色要求可靠色彩管理；若当前编解码路径不能正确解释 ICC，需降级提示，而不是无声丢弃配置。
- Alpha 混合应遵循统一的预乘约定；高精度操作尽量在一致的工作空间执行。
- 不能保证完整保留所有 EXIF/IPTC/XMP 时，应以实际支持的字段提示，不得笼统写“保留全部元数据”。

### 5.3 非破坏性会话（SYS-03，P0）

源图保持只读；编辑保存操作描述及参数快照；预览使用低分辨率缓存；最终导出重新读取源图运行同一算法或等价完整分辨率实现。关闭未导出的工作会话时可提示；不要求保存 PSD 类工程文件。模板/布局等创作型场景可使用项目自定义的轻量 JSON 会话文件（P2），但不承诺跨产品互通。

### 5.4 统一导出契约（SYS-04，P0）

1. 校验格式、路径、预计输出大小与内存预算。
2. 先写入目标文件目录下随机命名临时文件（在可行时便于同卷原子重命名）。
3. 编码完成、关闭文件句柄，重新检查输出文件可读取、格式与尺寸/帧数符合预期。
4. 最后执行提交/重命名；已存在目标必须显式处理。失败、取消清理临时输出。
5. 在磁盘不足、无权限、路径太长、同名冲突、损坏图片等情况下提供恢复动作；不能宣称输出成功。

**注意**：跨平台“原子覆盖已存在文件”的行为不同；Windows 上需单独实现并测试。不要把 `os.Rename` 当成普适的覆盖事务。

### 5.5 导出完成页（SYS-05，P0）

显示输出路径、图片尺寸、输出格式、文件体积、压缩比例（若有意义）、耗时；提供“打开图片 / 打开所在目录 / 复制图片 / 继续编辑”。图片尺寸或质量发生变化时突出说明；动画导出显示帧数、总时长、循环语义。

### 5.6 本地隐私与文件安全（SYS-06，P0）

- 默认本地处理，不采集上传源图；用户不需要注册账号。
- 非默认的联网行为仅限用户主动操作的模型下载、版本检查等，且设置中可关闭。
- 错误日志记录错误码、软件版本和阶段即可；默认不记录用户原始图片内容或完整隐私路径。
- 处理文件大小、解压后像素数、帧数、临时空间与中间缓冲预算，防止图片炸弹引发崩溃。
- 标注工具“永久敏感信息遮盖”采用不可透明的不透明覆盖并重新编码；不将普通高斯模糊当成安全脱敏。

## 6. 基础处理功能规格（BAS）

### BAS-01 格式转换（P0）

**场景**：将摄影照片、截图、透明素材和动图转换为适当的输出格式，保持内容、色彩与透明度可预期。

**子功能与行为**：
- BAS-01-01 导入单张/多张图（多张仅本工具内部逐项转换，不产生跨模块批处理管理中心）。显示格式、尺寸、Alpha 和动画信息。
- BAS-01-02 输出格式选择：P0 实测保证 JPEG、PNG；GIF 的输入/输出及 WebP 的具体读写能力由实际编解码注册表确定，未经验证不得作为 P0 承诺。P1 验证 BMP、TIFF、WebP；P2 评估 AVIF/HEIC/JXL/ICO 等。
- BAS-01-03 输入动图时弹出“保留动画（仅目标格式支持）/ 提取首帧 / 导出指定帧”选项；保留动画不能成功则提示，不可静默变成静态图片。
- BAS-01-04 JPEG 等无 Alpha 格式支持背景填充，可选色值；导出质量参数仅对实际有损编码器有效。
- BAS-01-05 元数据导出选项按“保留支持字段/清除隐私元数据/全部清除”处理，并标识无法迁移的项目。
- BAS-01-06 显示本次输出可用格式与不可用原因，提供源文件和目标文件体积比较。

**异常/限制**：伪装后缀、损坏头、未安装编码器、动图帧数过大、透明图转 JPEG、ICC 不受支持；均显示可恢复说明。

**验收**：①透明 PNG 转 JPEG 后背景是用户指定颜色、边缘无异常黑线；②方向标记为旋转的 JPEG 导出方向正确；③动态 GIF 导出 PNG 明示静态输出；④真实不能写出的格式在 UI 被禁用并解释原因；⑤用户取消后原图字节哈希不变。

### BAS-02 尺寸调整（P0）

- BAS-02-01 按像素/百分比/最长边/最短边调整；默认锁定宽高比。
- BAS-02-02 提供 Fit（完整适应）、Fill（裁切铺满）、Pad（保留完整内容并补边）、Stretch（故意拉伸，须警示比例变化）。
- BAS-02-03 重采样选项 Nearest、Linear、Catmull-Rom/Mitchell、Lanczos；给出“像素风/速度/平衡/清晰”的解释，不宣称所有图像单一算法最优。
- BAS-02-04 预设包含常见宽高比及自定义尺寸；允许保存当前工具内预设。默认禁止无意识放大。
- BAS-02-05 可选输出 DPI/PPI 元信息设置，但不得把单改 DPI 等同于修改像素分辨率。

**验收**：1000×500 输入，目标 400×400：Fit 内容应为 400×200；Fill 为 400×400 并裁切；Pad 输出为 400×400 且完整保留主体。无比例锁时会提示可能形变；超大目标尺寸会预估内存并阻断风险操作。

### BAS-03 图片裁剪（P0）

- BAS-03-01 自由裁剪，常用比率 1:1、4:3、3:4、16:9、9:16、自定义；输入像素级 X/Y/W/H。
- BAS-03-02 交互支持四边/四角拖动、移动裁剪框、居中、三分网格参考；边界与最小尺寸有约束。
- BAS-03-03 可调用共享的旋转、翻转与拉直；任意角可选择“扩展画布/裁去空白区域”。
- BAS-03-04 自动去白边/透明边根据颜色/Alpha 容差推算裁剪框；结果可手动修正，不能强制裁切。
- BAS-03-05 圆形与非矩形输出归类为“裁剪蒙版”，仅在支持 Alpha 的目标格式下输出透明形状，转 JPEG 时背景填充。

**验收**：裁剪框边界在预览和输出不偏移超过一个像素；对带 EXIF Orientation 的图片按旋正后的坐标裁切；自动去边不将内容主体误裁且可撤销。

### BAS-04 图片压缩（P0，核心竞争力）

**模式设计**：

| 模式 | 用户看到的选项 | 行为 |
|---|---|---|
| 保留画质 | “画质优先” | 高质量初始值、用户可调，不以体积为唯一目标 |
| 尽量减小 | “体积优先” | 支持编码质量、元数据、尺寸等策略组合，明确是否变更格式/尺寸 |
| 指定大小 | “目标体积” | 接受 KB/MB；给出达成、未达成和“最接近结果”状态 |
| 无损优化 | “不改变像素” | 仅使用真实无损编码/重排/元数据策略；不承诺一定变小 |

**需求细则**：
- BAS-04-01 提供输出格式（仅可用编码器）、图片质量、目标文件大小、必要时分辨率上限和元数据策略。
- BAS-04-02 指定体积采用有限次数参数搜索；误差默认目标 ±5% 作为建议值，并限制搜索次数以防 UI 卡死。输出文件大小对质量不保证严格单调；搜索失败应报告未达成，不得虚报成功。
- BAS-04-03 无法达到目标时提供“降低分辨率 / 改格式 / 接受当前最小结果”的明确选择，是否接受降尺寸须由用户授权。
- BAS-04-04 JPEG、PNG、WebP 的质量设置因编码器而异。PNG 无损编码不应展示虚假的 JPEG 风格质量滑块；PNG 有损量化必须标记为“减色/调色板”等真实行为。
- BAS-04-05 实时显示原图/预估/最终体积、缩减率、耗时；提供 100% 同步滑杆比较，P1 可以增加 PSNR/SSIM。
- BAS-04-06 若压缩后反而更大，提示并提供保留原件/仍导出；不能默认将更大的文件覆写源文件。
- BAS-04-07 可选文字截图/照片/动漫/透明 Logo 优化预设，保存的参数可见、可修改。

**验收**：照片、中文截图、动漫、半透明 Logo、噪点照片、纯色渐变分别检测；压缩结果有效可打开；按目标大小误差显示真实；透明边无异常；默认原图绝不覆盖；不能达成目标时显示清晰状态而非“成功”。

### BAS-05 基础图片编辑（新增，P1）

**定位**：把旋转/翻转/画布/边框等分散基础操作放在单个简单工作台，不承担专业色彩、复杂图层或标注的完整交互。

**子功能**：旋转 90°/180°/任意角、翻转、画布扩大与位置锚点、纯色/透明背景填充、圆角、边框、阴影、透明度、基础锐化/模糊、灰度与反相。可保存本工具内设置预设。对遮挡编辑后的图像，保证透明和边框渲染顺序一致。

**验收**：任何操作组合都可撤销重做；扩展画布不意外改变内容比例；圆角 PNG 输出透明正确，圆角 JPEG 输出明确使用背景色。

## 7. 创作与排版功能规格（CRE）

### CRE-01 宫格切图（P1）

**场景**：生成九宫格社交素材、多块连续图片或指定行列图片片段。

- CRE-01-01 固定预设 2×2、3×3、4×4，自定义行/列（建议限制 1–20、具体随设备预算调整）。
- CRE-01-02 可设置切割间距（仅切割源图/生成留白样式应区分）、切块边界预览、按行或按列编号。
- CRE-01-03 每块输出尺寸计算使用一致的整数边界分配，处理像素不能整除情况；默认无像素丢失/重叠。
- CRE-01-04 单块下载/全部导出 ZIP；默认命名 `原名_row-col.ext`，单功能内部输出，不建设文件管理界面。

**验收**：非整数均分尺寸如 1001×667→3×3，所有切片拼回源图的像素区域应连续、无空洞、无重叠（不含用户主动设置的视觉间距）。

### CRE-02 图片布局（P1）

**场景**：制作需要精确控制图层、文字、位置与装饰的图片画布。

- CRE-02-01 自定义画布宽高、背景色/透明、常用横竖比例与导出像素密度。
- CRE-02-02 图层类型：图片、文字、形状、背景。基本属性：X/Y、宽高、缩放、旋转、透明度、圆角、裁切蒙版、层级、锁定、隐藏。
- CRE-02-03 拖拽、等比例缩放、网格/中心线吸附、对齐与等距分布、复制/删除图层。
- CRE-02-04 支持模板选择、修改；P2 可保存可编辑的本地项目文件，格式文档化但不声称兼容 PSD。
- CRE-02-05 大画布渲染需提前校验内存，展示预估输出大小；允许分段导出属于工程优化，输出必须一致。

**验收**：两个半透明图层的叠放顺序正确；文本与图片对齐的最终输出坐标和画布预览一致；锁定图层不可被鼠标意外移动。

### CRE-03 图片拼图（P1）

**定位**：强调快速组合，不重复自由布局完整操作。

- CRE-03-01 一次导入 1–16 张图片（保留现有能力；超过 16 张另行评估）；自动生成规则网格、横竖混排、错落、拍立得等预设。
- CRE-03-02 拖动改变图片顺序；每个单元提供平移、缩放和重新适配，默认 Fill，允许切换 Fit。
- CRE-03-03 可设置格间距、外边距、圆角、背景色/背景图片、整体比例。
- CRE-03-04 预览和导出时不因图片加载顺序改变其他单元；支持不同来源图片的色彩一致性处理策略。

**验收**：等比例图像不变形；1、9、10、16 张不同方向图片在支持的模板下均可导出；重新排序后无图片重复/丢失。

### CRE-04 长图拼接（P1）

**定位**：连续内容的完整性与接缝准确性优先于美观模板。

- CRE-04-01 横向/纵向，顺序调节，统一宽度或统一高度，手动添加间距或分隔线。
- CRE-04-02 自动重叠识别：降采样预筛选 + 亮度/边缘相似度搜索 + 对齐置信度展示；应允许预览所认为的重叠区域。
- CRE-04-03 匹配失败或低置信度时自动回退到“手动调整接缝”，用户可输入偏移或使用可视对齐辅助。
- CRE-04-04 可将重复的固定顶部/底部导航栏标记为排除区域，避免滚动截图重复标题。
- CRE-04-05 结果过长而超过某格式/渲染器极限时提供分段输出或建议降低尺寸；不得因静默裁断导致内容丢失。

**验收**：正常滚动截图自动匹配无重复行；高度重复的大面积白底/悬浮按钮会给出低置信度提示；长图超限时提示并安全取消。

### CRE-05 批量水印（保留 P0，增强 P1）

- CRE-05-01 输入单张或多张；文本、图片 Logo、九宫定位、平铺。
- CRE-05-02 透明度、旋转角度、缩放模式、边距、文字描边与阴影；批量图像按原尺寸比例适配。
- CRE-05-03 支持本工具内部的 `{filename}`、`{date}`、`{index}` 变量，预览会显示每张图对应实际文本。
- CRE-05-04 可保存水印样式模板；失败文件逐项报告但不建设统一的跨工具任务中心。
- CRE-05-05 明确声明可见水印无法保证不可删除，不能以此替代数字版权保护。

**验收**：不同长宽比图片的水印位置一致且不溢出；Unicode 和中文文件名可以正确渲染；原图不被覆盖；部分失败可复查明细。

### CRE-06 富文本制图（P1）

**边界**：只将文字和元素排成可分享的图片；绝不扩展到 OCR 或扫描文档。

- CRE-06-01 支持标题、副标题、段落、引用、列表、代码高亮、卡片背景、分隔线、小图标和内嵌图片。
- CRE-06-02 可选择字体、字重、字号、行距、段距、最大宽度、自动换行、对齐、内边距和背景。
- CRE-06-03 可以输入简化 Markdown 作为**图片布局标记**，支持常见标题/粗体/代码块；不做文档格式导入和语义解析。
- CRE-06-04 图片可以按内容自动增长高度；导出时可选 1×/2×/3× 像素倍率，在安全预算内输出。
- CRE-06-05 中文标点挤压、换行和字体回退必须测试；缺字时给出提示，不能出现方框乱码后仍报告正常。

**验收**：长篇中文段落、英文代码、数字/标点混排清晰且不溢出；2× 图片相较 1× 字体边缘正确；不依赖网络加载外部字体。

### CRE-07 图片标注（新增，P1）

- CRE-07-01 工具：矩形、圆形、箭头、直线、自由笔、文字、数字编号、局部高亮、马赛克、模糊。
- CRE-07-02 对象选择/移动/缩放/层级/删除；线条颜色与粗细可改，箭头端点可编辑。
- CRE-07-03 “安全遮盖模式”：纯不透明区域覆盖，可设置颜色；导出合成为像素且默认清除无关隐私元数据。
- CRE-07-04 交互上区分“美观打码（模糊/马赛克）”和“不可逆遮盖（覆盖）”，并显示差异说明。

**验收**：安全遮盖导出后的被遮挡区域不保留底层像素；缩放图片后对象位置准确；导出后不会留下可编辑图层重新显示被覆盖内容。

### CRE-08 截图美化（新增，P1）

- CRE-08-01 支持导入现有截图；系统截屏捕获作为 P2，仅在桌面壳和 OS API 实际可用后上线。
- CRE-08-02 提供圆角、阴影、背景渐变/纯色/图片、留白、描边、容器边框、常用画布比例。
- CRE-08-03 可选浏览器/手机/桌面外壳样机作为轻量装饰模板，不承诺设备像素级物理仿真。
- CRE-08-04 生成的图片默认不截断截图实际内容；最大放大倍率由资源预算限制。

**验收**：透明和不透明源截图都能输出；阴影无不合理截断；四角圆角边缘无黑线；Windows 显示缩放变化不影响最终输出尺寸。

## 8. 专业图像功能规格（PRO）

### PRO-01 专业调色（P1）

**用户价值**：以简单控制覆盖常见照片修饰场景；高级用户能够校准曝光、颜色和反差，不必进入复杂图像编辑软件。

**参数面板**：

| 子模块 | 参数 | 核心交互及校验 |
|---|---|---|
| 基础曝光 | 曝光 EV、亮度、对比度 | 数值输入 + 滑块 + 双击复位；注明数学定义和范围 |
| 明暗区域 | 高光、阴影、白色色阶、黑色色阶 | 调整与直方图联动，不应出现无提示的严重裁切 |
| 颜色 | 饱和度、自然饱和度、色温、色调、白平衡 | 以适当颜色空间处理，避免误将 RGB 单通道偏置称作色温 |
| 色阶 | 输入黑/灰/白点、输出范围 | 提供重置与灰点控制，避免反向范围导致崩溃 |
| 曲线 | 总亮度曲线、R/G/B 分通道曲线 | 点拖动、添加/删除锚点、预设保存；端点不会出界 |
| HSL | 各颜色区间的色相/饱和度/明度 | 分区调整无明显边界断层，功能和数值范围有解释 |
| LUT | `.cube` 导入、强度 0–100% | 先支持已验证的 3D LUT；无效表/极端尺寸拒绝导入 |

**专业准确性**：曝光、光照融合、高精度曲线等原则上以线性光或定义清楚的工作空间计算；只有支持可靠 ICC/色彩空间转换的实现才可宣称色彩精确。优先保持 16 位或浮点工作中间数据，最终输出再量化；无法提供高位深能力时应标注为“8-bit 调色模式”，避免过度保证不出色带。

**交互**：拖动滑块产生低分辨率预览并取消过期任务；支持 100% 对比、恢复单项、整体恢复、撤销/重做。允许保存调色预设，但不引入云端预设市场。

**验收**：数值 0/默认值时输出与色彩管理归一后的源图一致（容差按编码器、像素格式定义）；重复切换参数不累计量化误差；ICC P3/Adobe RGB 样本不发生无声且明显的色偏；LUT 越界有明确错误。

### PRO-02 图片滤镜（P1）

**滤镜类别**：基础（黑白、反色、复古、暖色、冷色）、纹理（胶片颗粒、噪声、暗角）、图像算法（高斯模糊、运动模糊基础模式、锐化、浮雕、边缘检测、素描、像素化）、风格化（调色板减色与边缘组合的卡通效果）。

- PRO-02-01 每个滤镜有缩略图、中文名称、强度 0–100、必要的高级参数和效果说明。
- PRO-02-02 选择滤镜后能快速比较“仅滤镜效果”与源图；同一张图可使用一个滤镜或按需叠加多个滤镜，顺序可调整。
- PRO-02-03 已选滤镜参数存储为会话操作，不通过反复 JPEG 编码累积损失。
- PRO-02-04 对“油画”“漫画”“修复”等效果名称谨慎使用；未采用相应算法不得夸大效果。

**验收**：0% 强度不改变图像（容差内）；100% 强度与单次滤镜实现相符；半透明图边缘无异常黑边；快速切换滤镜时旧任务结果不会覆盖新预览。

### PRO-03 图片对比（共享 P0，独立增强 P1）

**目标**：全局可调用的真实像素质量检查器，是压缩、超分辨率、调色、过滤操作的重要共用组件。

- PRO-03-01 原图/处理结果左右分屏、拖动分割线、透明叠加、原图与结果快速切换。
- PRO-03-02 同步缩放、平移、1:1 像素定位、十字游标和 RGBA 取样；尺寸不同可选择“按同名相对位置”或“指定几何映射”对齐。
- PRO-03-03 P1：生成绝对差异图、热力图、PSNR、SSIM 指标；显示采用的对齐方式、评价参考图和色彩空间。
- PRO-03-04 P1：对压缩前后显示输入/输出大小、像素数和时间；对 AI 图显示实际倍率与算法提示。

**限制**：无对齐、不同尺寸或颜色空间不一致时，不自动输出误导性的质量分数。SSIM/PSNR 仅是参考指标，不能替代人工视觉评估。

**验收**：两图重采样和几何映射可复现；拖动到 0/100% 时完整显示对应图；色彩值取样与内部表示一致；不同尺寸未指定对齐时指标处于“不可计算”状态。

### PRO-04 图像分析（P1）

- PRO-04-01 显示 R/G/B/亮度/Alpha 直方图，支持对数纵轴和通道开关。
- PRO-04-02 显示过曝、欠曝像素分布、颜色取样、透明像素比例、近似不同色数量。
- PRO-04-03 图片信息区域显示像素格式、比特深度（可用时）、ICC、EXIF Orientation、动画属性；不强制提供完整元数据编辑器。
- PRO-04-04 大图默认使用分层采样或分块扫描，标注“采样统计/全量统计”，不误导为精确全图结果。

**验收**：纯黑/纯白/灰阶/半透明图测试下通道分布符合预期；用户关闭分析页时 CPU 和内存恢复；大量像素分配不能冻结界面。

### PRO-05 位图矢量化（P2）

**范围**：主要面向高对比 Logo、图标、简笔画、线稿；不宣传可将任意照片一键变成完美 SVG。

- PRO-05-01 基础纯 Go 路线：二值化 → 连通区域/轮廓提取 → 路径简化 → 曲线近似 → 输出真正的 SVG Path。
- PRO-05-02 允许调整阈值、平滑程度、路径节点数、是否背景透明、预览向量路径。
- PRO-05-03 彩色高质量描摹只有在独立适配器 PoC 与许可证批准后才开放，候选可参考 VTracer。

**验收**：输出 SVG 可以独立缩放而非只是 `<image>` 内嵌位图；闭合轮廓没有明显自交或孔洞丢失；退化输入可安全报错。

### PRO-06 图片融合/堆栈（P3）

只保留技术预研题目：多图平均降噪、曝光融合、简易焦点堆栈；需图像配准、曝光一致性和鬼影处理，开发成本高，**不作为本 PRD 的发布承诺**。若后续确有用户证据，应独立立项和定义测试图集。

## 9. 动态与素材功能规格（MED）

### MED-01 GIF/动图工具（现有入口强化，旧能力 P0 / 扩展 P1）

**核心场景**：用户能正确查看、剪辑、合成和优化 GIF；在可靠编码器存在时进行 APNG 与动态 WebP 互转。

**帧操作**：
- MED-01-01 打开 GIF，播放/暂停/逐帧/循环；时间轴显示缩略图、序号和帧时长。
- MED-01-02 逐帧删除、复制、顺序拖拽、反向播放；修改单帧时长和整体速度倍率。
- MED-01-03 GIF 转 PNG 序列；静态图片序列→GIF；动图裁剪、缩放、添加文字；导出图片序列可使用当前工具的 ZIP 输出而不是图片管理中心。
- MED-01-04 调色板限制、颜色数、量化方式、抖动强度、背景/透明色、优化质量模式和输出体积预估。
- MED-01-05 选择循环次数、循环永远/指定次数；动画在播放和导出时应正确表达格式本身的循环语义。
- MED-01-06 P1：APNG 与动态 WebP 解码/编码分开测试，支持能力以运行时格式表为准，不承诺互转所有组合。
- MED-01-07 P2：优化帧间差分，导出前比较质量与体积；P2 视频→动图依赖可选视频解码组件。

**关键业务规则**：GIF 帧可能只存画布一部分，必须先按 disposal/offset/透明规则构建“可显示完整帧”，编辑后重新量化/封装；不能将 `gif.GIF.Image[i]` 直接解释为屏幕完整帧。各动画格式的时长单位、循环次数和合成规则不同，内部须规范化，再按目标格式编码。

**验收**：准备含局部更新、Restore to Background、Restore to Previous、透明叠加、非均匀时长、循环次数的测试 GIF。导入播放、编辑后保存、再次打开，与预期画面和时间轴一致，不出现黑帧、闪烁、错位或时间漂移。取消处理不覆盖原 GIF。

### MED-02 图标生成（P1）

- MED-02-01 输入带透明或不透明背景的图片，选择生成 ICO、Favicon PNG 等用户可见图标；不是开发者资源管理中心。
- MED-02-02 ICO 常用 16/24/32/48/64/128/256 像素尺寸集合，用户可选输出尺寸；支持预览不同尺寸的清晰度。
- MED-02-03 图片适应模式 Fit/Fill/Pad、透明背景、边缘留白、安全区域及圆角外观预览（不默认为 ICO 破坏原始透明形状）。
- MED-02-04 生成多尺寸 ICO/单独 PNG/ZIP；如果内部 PNG-compressed ICO writer 为纯 Go，自测 Windows Explorer 及常见图像查看器兼容性。

**验收**：标准 Windows 图标能正确显示 16/32/256 层；透明角边缘无黑线；尺寸不足时明确提示会发生上采样。

### MED-03 色彩提取（P1）

- MED-03-01 图片上任意像素取色，显示 HEX、RGB、HSL、HSV、Alpha；实时放大镜。
- MED-03-02 主色提取：用户选择 3/5/8/10 色；显示颜色占比、生成可复制调色板。
- MED-03-03 配色建议：互补、类似、三角、明暗变化和渐变示例；配色建议与真实像素统计结果分开标识。
- MED-03-04 文字与背景的 WCAG 对比度计算，作为图片视觉可读性的参考。
- MED-03-05 默认忽略完全透明像素；半透明像素可选在指定背景下合成后采样。

**验收**：指定单色输入应提取该颜色；透明 Logo 的主色不被透明黑像素污染；拾取值复制后与界面一致。CMYK 如展示只能列为参考转换，不作为印刷打样依据。

### MED-04 视频帧提取（P2，可选视频组件）

- MED-04-01 用户选择视频、时间点/时间间隔/抽帧 FPS，预览所选帧并导出 PNG/JPEG。
- MED-04-02 支持提取单帧、每隔 N 秒抽帧、限定区间以及 3×3 故事板。
- MED-04-03 对可变帧率与不同封装格式，抽帧规则应明确基于视频时间戳还是顺序帧号。
- MED-04-04 禁止在基础包里自行实现完整 H.264/H.265/AV1 解码器。使用经合规检查的 FFmpeg 独立适配器，只有安装且版本验证成功后显示相关选项。

**验收**：输入不支持的编码格式应解释“缺少视频组件/不兼容”；提取时间戳在已知测试视频允许误差内；视频文件不被覆盖。没有 FFmpeg 组件时其他图片功能全部正常。

### MED-05 像素画与点阵图（P1）

**产品特色场景**：像素艺术、电子纸、复古游戏素材、自定义屏幕图像，包括 400×300 纯黑白图。

- MED-05-01 支持目标分辨率、保持比例/裁切/补边、最近邻放大与像素网格展示。
- MED-05-02 色数 2/4/8/16、灰阶或自定义调色板；严格黑白模式保证输出像素值只有黑/白且无半透明。真正的 1-bit PNG 另要求 IHDR bitDepth=1；colorType 为 0 或 3，索引模式有效调色板仅含黑白；透明输入先按显式背景合成。普通 RGB 黑白 PNG 不得标记为 1-bit 编码。
- MED-05-03 抖动算法 None、Bayer Ordered、Floyd–Steinberg、Atkinson；支持算法说明、强度、亮度阈值与色彩反相。
- MED-05-04 可提供黑白 400×300、4:3、1:1 等预设，允许用户新建/保存尺寸预设。
- MED-05-05 输出推荐 PNG 或其他支持无损且能表达目标调色板的格式；如导出 JPEG，应提醒其可能产生中间灰度和压缩伪影。

**验收**：二色严格模式抽样全图每像素为指定两种色值之一；固定随机种子时处理可复现；含细小中文和黑白线条的测试图不被意外平滑成灰色。

### MED-06 表情包制作（P1）

- MED-06-01 静态模板（上下字幕、全屏图文、头像贴图、对话气泡）、文字描边、填充、阴影、透明背景。
- MED-06-02 自定义字体和版式，内置模板无需联网下载；对中文字体提供可靠回退策略。
- MED-06-03 GIF 表情制作：叠加文字至全部帧或指定帧区间；支持帧数/总时长/文件大小提示。
- MED-06-04 可选平台大小预设但不保证随各平台实时变化，提供用户自定义限制。

**验收**：静态表情不截断文字，动态表情字幕时间对应正确帧；导出后循环、透明色和预览保持一致。

### MED-07 背景/素材生成器（P2）

- MED-07-01 纯 Go 生成纯色、线性/径向渐变、棋盘、条纹、网格、圆点、简单几何图案、程序化纹理。
- MED-07-02 支持画布宽高、前景/背景色、重复密度、旋转、渐变起止位置、随机种子、透明背景。
- MED-07-03 生成过程应确定性：相同参数和种子得到像素等价结果。

**验收**：极小和大尺寸输入无越界；平铺纹理在设计为无缝模式时四边可对齐；不调用在线图片生成服务。

## 10. 智能增强功能规格（AI）

### AI-01 本地 AI 高清放大（P1，独立可选发布线）

#### 10.1 产品定位与边界

“**Upscayl 类体验**”指本地 AI 超分辨率：图片增强、不同图像类型模型、倍率、局部对比、导出与 GPU 运行状态。**不等于复制 Upscayl 的 UI、代码或声称支持它全部专有模型和参数。** 如果使用上游官方品牌或模型名称，应根据实际兼容性和商标、许可证要求正确表述。

#### 10.2 功能需求

| ID | 子功能 | 用户行为与规则 | 验收要求 |
|---|---|---|---|
| AI-01-01 | 环境探测 | 打开页面显示推理引擎、版本、GPU 可用性、驱动及模型状态 | 真实不可用设备不显示“可加速” |
| AI-01-02 | 图片导入 | 导入 PNG/JPEG 和真实可解码格式，提示输入尺寸与输出预测 | 不因输入宽高极端值崩溃 |
| AI-01-03 | 模型选择 | 展示“适合照片/插画/动漫”的模型用途、原生倍率、安装状态和来源 | 与本机引擎兼容列表一致 |
| AI-01-04 | 放大倍率 | 选择原生倍率；非原生目标尺寸采用推理后 Go 缩放并明确提示 | 不假称模型天然支持任何倍率 |
| AI-01-05 | 局部预览 | 选定局部区域，运行相同模型的局部推理，提供前后比较 | 明示局部与整图上下文差异 |
| AI-01-06 | 设备高级设置 | GPU、Tile=Auto/指定大小、TTA 等仅在后端支持时显示 | 参数校验，不将一个引擎参数误传另一引擎 |
| AI-01-07 | 执行与取消 | 显示当前阶段、耗时、进度（若引擎可提供）、取消、错误和重试 | 取消后无后台遗留推理与伪结果 |
| AI-01-08 | 导出 | PNG 默认输出，其他格式按引擎及 Go 后处理能力动态决定 | 结果可解码、尺寸与期望匹配 |
| AI-01-09 | 模型管理 | 安装/移除/查看来源/校验哈希/兼容性检查/占用空间 | 不加载损坏或不兼容模型 |
| AI-01-10 | 完整隔离 | AI 组件缺失、GPU 错误、模型卸载不影响 Core | Core 全部高频用例通过 |

#### 10.3 关键状态与故障体验

- **未安装引擎**：明确显示“需要安装本地高清放大组件”，提供安装说明或可信内置组件安装界面；基础产品不强制下载。
- **模型缺失**：列出模型名称、体积、来源与许可证信息（经审核），可下载或导入；不能偷偷自动安装。
- **GPU 不兼容**：显示检测原因（无 Vulkan/驱动异常/显存不足/引擎测试失败）；不承诺可用 CPU 备用，除非有单独实现且验证。
- **GPU OOM**：建议降低 Tile、关闭 TTA 或选择更轻模型；允许重试且回收上次失败的进程和临时文件。
- **任务取消**：请求取消→优雅关闭子进程→超时强制终止→检查临时输出→返回页面 READY；必须处理 Windows 子进程/孙进程残留情况。
- **输出失败**：明确区分推理失败、磁盘失败、编码失败、文件校验失败；全部以文件实际成功校验为准。

#### 10.4 源码核对与实现选择

[已确认·上游] Upscayl 的 Electron 主程序使用 `child_process.spawn()` 调用独立 `upscayl-bin`，模型和参数在桌面宿主侧组织；原生推理基于 NCNN/Vulkan。因此，Go 重写主程序/任务调度能减少 UI 宿主框架负担，但**相同模型和 GPU 下不能推断推理速度因 Go 而必然更快**。

[已确认·上游] `upscayl/upscayl-ncnn` 使用 AGPL-3.0；`xinntao/Real-ESRGAN-ncnn-vulkan` 项目采用 MIT 许可证，其 CLI 使用 `-i/-o/-s/-t/-m/-n/-g/-j/-x/-f` 等参数，但不承诺与 Upscayl fork 的 `-w/-c` 兼容。模型权重和二进制依赖仍要单独审查许可证。

**推荐方案**：Go UI/服务 → `UpscaleEngine` 接口 → 经版本校验的 Real-ESRGAN-ncnn-vulkan 独立进程 → 临时结果 → Go 校验并保存。第二适配器仅在需要、合法且测试通过时接入 `upscayl-ncnn`，不得把两者当成相同 CLI。禁止通过 shell 拼接用户路径构造命令；使用受信任绝对路径、显式参数列表与哈希校验。

#### 10.5 性能对比规则

比较 Go 宿主与 Upscayl Electron 宿主，必须统一：输入源图、模型文件 SHA256、推理后端版本、GPU 与驱动、Tile、TTA、输出格式、冷/热启动条件。指标包括：主程序与所有子进程合计内存、UI 首次交互时间、推理端到端耗时 P50/P95、峰值显存、结果质量。只有测试真实数据通过后才能使用“更轻/更快”的文案。

#### 10.6 模型分发与合法性

核心包默认不包含未经授权的权重；模型包须拥有来源、版本、SHA256、原生倍率、兼容架构、许可证链接、分发审查状态。未经许可审查不得自动打包或推广模型。AGPL 组件采用独立进程**不自动消除**许可证义务，应由发布方审查分发架构，具体合规建议不等于法律意见。

### AI-02 智能抠图（P2）

仅在 AI-01 的隔离机制稳定、具备合适模型来源与许可证、真实效果达到门槛时独立立项。潜在范围：人物/商品主体分割、透明背景、背景替换、简单蒙版修边；不将粗糙背景颜色阈值冒充智能抠图。

### AI-03 旧照片修复/智能擦除（P3）

不列入版本发布承诺。超分辨率、去模糊、修复和对象擦除是不同模型任务；目前不能仅靠 Real-ESRGAN 就声称具备完整旧照片修复或任意对象移除能力。

## 11. 非功能需求（NFR）与运行环境

### NFR-01 性能和响应性

**以下为建议验收门槛，不是当前项目或 Go 框架已达到的事实。** 在 M0 锁定硬件、版本、文件样本和当前基线后，可经 ADR 调整。

| 指标 | 运行条件 | 目标与说明 | 验收方式 |
|---|---|---|---|
| 冷启动至可交互 | Win11 x64、中档 SSD、无 AI 后台 | 建议 P50 ≤ 2 s，P95 单独记录 | 完全退出后重复 20 次，统计分布 |
| 空闲内存 | 启动、无输入图片、无 AI 子进程 | 争取主应用 + UI 相关进程 P50 ≤ 150 MB；以实测基线校准 | Windows 私有工作集及子进程总和 |
| 中等图片首屏预览 | 2000×1500 JPEG、测试机 B | P95 ≤ 600 ms；快速呈现缩略图可先于精确 ICC 完成，但须避免颜色瞬变 | 30 次含文件解码、缩放、显示 |
| 参数交互反馈 | 2000×1500 输入、低清预览 | 拖动反馈与最终预览 P95 ≤ 250 ms；重滤镜可显示忙碌并取消旧任务 | 连续滑杆测试 + 任务序号断言 |
| 主线程阻塞 | 大图/动图处理 | UI 不出现长期无响应；耗时操作有取消 | 8K 输入、120 帧 GIF 极端用例 |
| 大图片内存 | 8K+、超宽长图 | 有明确预算和拒绝/降级机制，不导致 OS 强制杀死应用 | 内存峰值、GC、页面响应 |
| 导出数据安全 | 无权限/磁盘满/异常终止 | 不能产生被误认为成功的文件，原图不可损坏 | 故障注入与哈希校验 |
| AI 负载 | 相同模型/引擎/GPU | 以全进程 RSS、显存、P50/P95 对比；不预设“Go 推理更快” | 与官方桌面宿主 A/B 对照 |

测试机 A：Windows 11 x64、8 GB RAM、常见核显或低功耗 CPU；测试机 B：Windows 11 x64、16 GB RAM、中档独显或等效。**这只是建议测试分层，不能代替实际目标用户硬件调查。**

### NFR-02 离线、隐私与网络

所有 Core、Creator、Studio 和不需要安装视频组件的 Media 功能离线可用。网络请求只用于明确的更新检查、由用户主动触发的模型/组件安装（如实施），并提供关闭入口；模型下载需要显示体积、版本、来源与用途，不自动上传用户图片。任何可选云端功能必须另行 PRD 和用户授权；当前无此计划。

### NFR-03 可靠性与错误分类

| 错误码 | 对用户的解释 | 建议操作 |
|---|---|---|
| `CORRUPT_IMAGE` | 图片损坏或数据不完整 | 更换文件、尝试其他格式 |
| `UNSUPPORTED_DECODE` | 无法读取该格式或动画 | 查看编解码能力、安装已审核扩展 |
| `UNSUPPORTED_ENCODE` | 当前环境不支持输出目标格式 | 更换可用格式 |
| `TOO_LARGE` | 图片像素数、帧数或预计内存超限 | 降低尺寸、减少帧数或按建议处理 |
| `INVALID_COLOR_PROFILE` | 图片色彩配置无效/不支持 | 选择明确降级策略，不静默转换 |
| `EXPORT_PERMISSION` | 目标目录无写入权限 | 另选目录 |
| `DISK_FULL` | 存储空间不足 | 释放空间，重试 |
| `MODEL_MISSING` | AI 模型未安装或缺损 | 导入/安装合法模型 |
| `GPU_UNAVAILABLE` | 没有兼容的 GPU 推理环境 | 诊断显卡与驱动，不宣称 CPU 能直接替代 |
| `ENGINE_FAILED` | 本地推理进程异常终止 | 查看本地错误详情、尝试更小 Tile |
| `CANCELLED` | 用户取消了任务 | 清理临时文件，保留当前会话 |

要求错误与功能状态分开：失败的后台任务不应把页面保留在永远“处理中”。每个错误必须可复制简短诊断信息（不默认包含隐私图片数据）。

### NFR-04 输入安全

所有外部图片都视为不可信输入：检查魔数、合理像素/帧数上限、分配前内存预算；独立 GPU/视频组件必须通过绝对路径执行，不通过 `cmd /c` 或 `sh -c` 拼接用户路径；不得以文件扩展名判断内容可信。下载模型和可执行文件校验 SHA256；对图片解析器、动图帧头、ICO、SVG 导入进行畸形输入 fuzz 或等价压力测试。

### NFR-05 字体、中文与国际化

简体中文为首要界面语言，可扩展英文；字串使用 UTF-8；必须测试中文文件名/路径/空格/emoji 文件名；图文生成支持字体 fallback，避免缺字方框、字距异常、字体许可违规。动态生成图片中字体的渲染结果必须可复现，不随预览与最终导出发生不可解释的换行差异。

### NFR-06 安装、升级、兼容

基础交付保留现有六平台构建、签名更新清单及升级兼容。既有配置、最近工具、侧栏顺序和拼图预设升级必须保留；旧 `RailOrder` 索引需映射到稳定工具 ID 后再新增或重排入口。不强制安装 AI 模型。保留 MyGo + Lobe MyGo，不新增 WebView 壳。云端构建与原生交互验收分别记录；新功能仅在实测平台声明可用。

### NFR-07 可观测性与诊断

提供本地可查看的程序版本、核心编解码能力表、各外部组件版本、模型列表、最后一次失败错误码；性能分析日志仅在用户主动开启时记录 CPU、耗时、内存摘要，不包含图像内容。M0 建立复现环境与匿名性能数据规范，**不要求上传遥测**。

## 12. 实施约束与技术决策（Implementation Constraints）

> 本章明确实施边界，不代替正式架构设计文档。具体包版本、主分支 API、性能必须在目标仓库中 PoC、锁版本和测试后决定。

### 12.1 总体架构（TECH-01）

```text
桌面 UI（维持现有稳定界面，或经论证后选择 Go 桌面壳）
  │  本地事件/函数调用
  ▼
Go 应用服务层
  ├─ 会话状态 / 撤销重做 / 参数校验 / 错误展示
  ├─ 图像信息与格式能力注册表
  ├─ 缩略预览 / 缓存 / 任务取消 / 导出事务
  ├─ Go Image Core
  │    ├─ 解码/编码       ├─ 几何/滤镜/颜色
  │    ├─ 画布/文字/图层 ├─ 动画帧语义
  │    └─ 直方图/差异/量化/抖动
  └─ 可选适配器（与基础功能彻底隔离）
       ├─ NCNN/Vulkan AI 放大
       ├─ FFmpeg 视频解码
       └─ 特殊格式编解码（经审核）
```

图像操作统一返回可取消的任务结果及实际输出能力；静态图与动图使用不同数据模型，防止丢失帧时长/循环/Offset/Disposal 信息。共享预览层可以复用操作描述，但不能假定每个操作都可对任意帧独立执行。

### 12.2 技术路线选择（TECH-02）

| 能力 | 首选 | 备选/注意 | 决策状态 |
|---|---|---|---|
| JPEG/PNG/GIF | Go `image/jpeg` / `image/png` / `image/gif` | 动图 GIF 必须实现完整可显示帧合成 | 默认可采纳 |
| 缩放/裁剪/旋转 | `disintegration/imaging`、`golang.org/x/image/draw` | 可根据基准自建小范围加速 | 默认可采纳 |
| 滤镜 | `disintegration/gift` | `bild` 等候选需要检验 Go 版本和性能 | 默认可采纳 |
| BMP/TIFF/WebP 解码 | `golang.org/x/image` 相应包 | WebP 编码不可混同于其解码 API | 逐格式测试 |
| WebP/APNG 动画 | 保留 `gen2brain/webp`、`kettek/apng` 与现有动画内核 | 分别验证读写、帧合成、时序和资源预算 | 已有回归；增量补边界 |
| 文字/图层 | Go 图像绘制与字体库，薄封装 | 中文排版、复杂 shaping、emoji 需专项测试 | 验证后定 |
| 色彩空间管理 | 保留 LCMS/WASM 及 ICC 现有路径 | 16-bit/float 与专业调色精度仍需验证 | 已有回归；非完整专业验收 |
| ICO | Go 原生 Writer / 小型成熟库 | 多尺寸 Windows 实机兼容测试 | 验证后定 |
| PNG/JPEG 压缩 | 保留 OxiPNG、jpegli 及现有质量策略 | 同时保留 libwebp/libavif；替换须提供基准与兼容证据 | 既有实现增量维护 |
| GIF 优化 | Go 量化 + 正确帧合成 | 高品质 GIF 外部编码器作为后续评估 | 初版原生 |
| AI 高清放大 | Go 进程管理 + Real-ESRGAN NCNN/Vulkan 二进制 | Upscayl-ncnn AGPL 仅合规审查后可选 | 默认选 MIT 路线 |
| 视频帧提取 | 可选 FFmpeg | 原生解码不可合理在本轮从零实现 | P2 可选 |
| 彩色矢量描摹 | 高级适配器如 VTracer | 仅基础黑白轮廓优先 Go | P2 可选 |
| 高吞吐处理 | 先 Go profiling | `libvips`/CGO 仅当有实测瓶颈且许可/部署可控 | 不默认依赖 |

### 12.3 GUI 决策门槛（TECH-03）

当前确定保留 MyGo + Lobe MyGo，不以换壳为实施前置任务。以下替代框架仅作为历史候选；重评须有实测瓶颈和用户批准。用户希望 Go 原生化，落地含义为“图像处理、任务调度、预览/导出契约和常规流程尽可能由 Go 提供”。如果现有前端已成熟，可保留并薄化，而不是不必要地重新制作所有 UI。若确需换壳：

- **Wails / 系统 WebView**：Go 处理逻辑 + HTML/CSS/JS 界面；不会捆绑 Electron 的完整 Chromium，但 WebView 本身仍有进程和内存消耗，**不能自称 100% Go 原生控件**。
- **Fyne 或 Windows 原生 UI 绑定**：可以更靠近 Go UI/原生小部件，但复杂画布、富文本、GIF 时间轴需要验证可用性与开发成本。
- **现有前端**：优先比较启动、常驻 RSS、事件延迟、拖动预览表现、Win 打包和兼容性。架构决定须来自 M0，不在 PRD 强制锁死一个框架。

### 12.4 Go 库升级风险（TECH-04）

`kovidgoyal/imaging` 公开 README 声称具备 ICC、动画 WebP/APNG 等能力，`go.mod` 标注 Go 1.26；`bild` 当前主线依赖 Go 1.25。当前已为 Go 1.27.3，不存在升级到 1.25/1.26 的任务；也不因候选库功能描述而替换现有实现。是否采用取决于现有 `go.mod`、Windows 编译环境、API 稳定性、动画编码与色彩结果。应做实验分支，不应为单个库盲目升级整个程序。某些库会在格式不支持时回退外部 ImageMagick；如果坚持纯 Go 核心，必须**在 PoC 中明确关闭或隔离该回退**，不能把外部执行伪装成纯 Go 实现。

### 12.5 统一格式能力注册（TECH-05）

建议内部能力按维度表示：`decode / encode / animatedDecode / animatedEncode / alpha / metadata / ICC / bitDepth / requiresPlugin / minimumVersion`。每个功能依据**真实安装组件与回归数据**展示选项；发布构建可导出实际支持矩阵，作为测试与用户帮助页的单一事实来源。

### 12.6 模块化界面/服务边界（TECH-06）

核心服务建议划分为：`codec`、`geometry`、`color`、`filter`、`canvas`、`animation`、`analysis`、`preview`、`export`、`capabilities`、`upscaleAdapter`。每个功能对外暴露需求操作而不是直接操作第三方库细节。接口必须支持错误分类和任务取消；不新增面向终端用户的 CLI/API；保留现有两个 CLI 的兼容协议。

### 12.7 许可证与安全决策（TECH-07）

每个进入发布产物的库、二进制、字体、模型单独记录：名称、上游仓库、版本/commit、SHA256、许可证文本、修改情况、是否需要源代码提供、是否可再分发、补充 NOTICE。升级时复核许可；此项为发布阻断门槛。特别注意 Upscayl AGPL 与 Real-ESRGAN-ncnn-vulkan MIT 不是同一授权，不能通过更换可执行文件扩展名规避许可证义务。

## 13. 数据结构与接口契约（产品层要求）

本章定义服务与 UI 应当交换的信息，字段为**逻辑契约**，不强制使用这些 Go 命名。

### 13.1 ImageAsset（单图引用）

`assetId, displayName, sourcePath, detectedFormat, width, height, bytes, frameCount, hasAlpha, bitDepth, iccInfo, orientation, metadataSummary, loadState`。只在当前会话持有源图引用，用户取消/关闭后可释放内存；不自动复制图片到永久缓存。

### 13.2 EditSession（编辑会话）

`sessionId, sourceAssetIds, activeTool, operations[], cursor, selectedObject, previewCacheKey, exportProfile, dirty`。操作记录包含 `operationId, parameters, enabled, order, version`，回退操作只改变参数/对象结构，不默认将大图每个版本保存成 PNG。

### 13.3 FrameSequence（动图）

`canvasW, canvasH, frames[{imageRef, offsetX, offsetY, duration, blend, disposal}], loopCount, totalDuration, colorPolicy`。动画预览使用正确复合帧；编辑时需要指明“修改当前显示整帧”还是“修改原始编码增量帧”。跨格式转换时必须校验两者表现一致。

### 13.4 RenderJob / ExportResult

`jobId, stage, progress?, cancellable, memoryEstimate?, errorCode?, errorMessage?` 和 `success, outputPath?, bytes?, width?, height?, frames?, format?, duration?, warnings[]`。进度可为空/不确定；不能因无法精确获取 NCNN 进度而虚拟完成百分比。

### 13.5 CapabilitySnapshot

`formatCapabilities, aiEngines, models, videoDecoderAvailable, colorManagementMode, installedComponents, engineVersions, warnings`。设置页、导出菜单与错误提示使用同一个快照结果，避免不同页面对格式支持说法不同。

### 14.2 验收规则（QA-02）

- **功能正确性**：每个功能必须覆盖正常路径、错误路径、撤销/取消、导出后重开，以及不同长宽/透明属性。
- **视觉正确性**：图片对比至少检查边缘/色彩/透明；结构化操作优先像素级或近似数值断言而不是仅凭肉眼通过。
- **性能正确性**：所有报告包含中位数 P50、P95、峰值 RSS、总分配字节（可采集时）、进程总内存、样本 SHA 和硬件信息。
- **平台正确性**：Windows x64 的正式候选发布包必须在干净系统上安装/卸载；其他平台无完整测试不可列为正式支持。
- **安全正确性**：源文件在所有失败、取消、磁盘耗尽、断电等模拟场景下不被非授权修改。

### 15.1 发布版本建议

- **Core 稳定更新**：优先改善原 14 个入口中核心工具的正确性；新增统一对比和导出能力。旧转 PDF 冻结。
- **Creator + Studio 更新**：上线创作画布和专业调色，把功能层级清晰化。
- **Media 更新**：完善 GIF、像素画、图标、表情包等素材方向。
- **AI Add-on**：在不影响基础包发布节奏的情况下独立迭代。

上述是建议功能包顺序，不强制以四个商业 SKU 发布；常用模块可以按成熟度分批合入。

### 15.2 阻断型决策点（Gates）

- **Gate A / M0**：必须拿到源代码、go.mod、UI 实现和测试包，确认真实能力与项目最低系统要求。
- **Gate B / 编解码**：证明关键格式的实际读/写、动画、Alpha 和 ICC 行为，才进入导出下拉框。
- **Gate C / 颜色**：确认色彩管理正确性，否则高级调色只能标为有限精度模式，不得宣称专业色彩准确。
- **Gate D / AI**：确认二进制、模型权重、许可、完整 GPU 错误流程，才能打包分发。
- **Gate E / 发布**：性能、原图保护和关键 E2E 全部满足，且迁移策略可验证。
